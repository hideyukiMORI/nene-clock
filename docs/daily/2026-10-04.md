## 1. 🔴 施主が言っていない要件が、仕様に入っていた

施主（2026-10-04）:「僕が Stopwatch/Timer を要件に入れたことは一度もない。機能が欲しいと言ったためしもないし、入れる予定もない。」

経緯はリポの記録で追えた。[2026-09-03 の日報](2026-09-03.md) 第 1 節に、施主が持ち込んだ外部 AI との草案を
「素材として全部取り込み」と書いてある。**草案の機能一覧が、施主の要件かどうかを確かめないまま FR になった**（`acc7f4d`）。
同じ日に Issue #15〜#17 が立ち、README は公開の場で「まだのもの」と言い続け、引き継ぎ書は「次の 1 手は #15」と書いていた。
1 か月後、hub がその Issue を見て「予定の機能」として 1.0.0 の判断材料に乗せ、施主に訂正された。

**草案は規約の素材にはなったが、要件の出どころにはならない。** 規約は ID を付けて機械強制の状態を確かめたのに、
機能のほうは誰が求めたのかを確かめなかった。`planned` を `active` と書かないことには厳しかったが、
「要件でないものを予定と書く」ことを止める仕組みは無かった。

判断したこと:

- FR の番号は詰めず、欠番の見出しで残した（過去の日報・引き継ぎ書・Issue が番号を指している）
- README は「まだのもの」の文を消しただけ。「今後は何も足さない」とは施主は言っていないので、書き足していない
- SWG-005（刻みは時刻の正本ではない）は時計にも当てはまるので残し、「減算カウンタの検出」だけを planned から不採用にした。
  数えて持つ値が製品に無く、planned のままだと来ない予定を予定と書くことになる
- 過去の日報と引き継ぎ書は書き換えていない

## 2. Store に出せるか（実測）

| 点 | 結果 |
| --- | --- |
| app-image を MSIX に包めるか | 包めた。配布済み v0.2.6 の zip の中身をそのまま。`C:\Program Files\WindowsApps\` に入れた状態で動いた |
| `java.util.prefs` の行き先 | **読むのは本物のレジストリ、書くのはパッケージ専用の場所。** MSI 版の設定は引き継ぐが、書き戻さない |
| CI の Windows ランナー | `makeappx` / `makepri` がある（SDK 10.0.26100.0・PATH には無い）。同じ app-image を包めた |

製品コードを変えないと包めない箇所は無かった。詳細と、測っていないことは報告にある。

測り方で守ったこと:

- 施主は MSI 版を常用している。**本物の設定キーは読むだけにし、書き込みは隣に作った検証用のキーで測った。**
  控え（`reg export`）と、実測後・アンインストール後の書き出しは SHA-256 が同じ
- 開発者モードの登録で測れること（身元・レジストリ）と、測れないこと（読み取り専用の場所）を分けた。
  後者は施主が自分でスクリプトを実行し、UAC を 1 回通して測った
- CI の実測は PR に一時的な手順を置いて行い、同じ PR の中で消した
