## 2. Store に出せるか（実測）

| 点 | 結果 |
| --- | --- |
| app-image を MSIX に包めるか | 包めた。製品コードを変えずに、`C:\Program Files\WindowsApps\`（読み取り専用）に入れた状態で動いた |
| `java.util.prefs` の行き先 | **読むのは本物のレジストリ、書くのはパッケージ専用の場所。** MSI 版の設定は引き継ぐが、書き戻さない |
| CI の Windows ランナー | `makeappx` / `makepri` がある（SDK 10.0.26100.0・PATH には無い）。同じ app-image を包めた |

測り方で守ったこと:

- 施主は MSI 版を常用している。**本物の設定キーは読むだけにし、書き込みは隣に作った検証用のキーで測った。**
  控え（`reg export`）と、実測後・アンインストール後の書き出しは SHA-256 が同じ
- 開発者モードの登録で測れること（身元・レジストリ）と、測れないこと（読み取り専用の場所）を分けた
- 信頼ストアを書き換える操作（自己署名の証明書）は、リナの権限では通らない。**スクリプトを置いて施主が実行した。**
  信頼を入れるのと消すのを 1 つの昇格の中に閉じ、インストールが起きなくても時間で消えるようにした
- CI の実測は PR に一時的な手順を置いて行い、同じ PR の中で消した

## 3. 作ったもの

### 3.1 `packageMsix`（#116 / #117）

`packageInstaller` が作った app-image を**そのまま**包む。作り直さない。包んだものを開き直して、全ファイルの SHA-256 が元と同じであることを task が確かめる。
身元は `app/src/msix/store-identity.properties`（施主が Partner Center から貼った値）。署名しない。
`makeappx` / `makepri` は SDK の版のフォルダを名指しし、名指しが外れたら落ちることを CI で実測した。
ロゴ 25 枚は `AppIcon` から寸法ごとに描く（縮めた絵を使い回さない）。

### 3.2 窓の下限（#97 / ADR 0021）

Store の実測で施主の実機の窓を測ったら 320×160 だった。同じ設定（Anton 56pt・秒あり・日付あり・余白 8）の自然な大きさは 212×133 である。
Issue #97 は「小さい設定での端の事例」として書かれていたが、**施主が毎日見ている時計がその事例だった。**
下限を「クロームが収まる大きさ」だけにした。**公開されると施主の窓は小さくなる**（頼んだ余白のとおりになる変化）。

### 3.3 作り直さずに公開する（#132 / ADR 0022）

タグは Store の認定のあとに打つ（施主の指示・Loupe と同じ順）。すると、Store に出す MSIX を作る実行と、タグで MSI・zip を作る実行が別になり、
同じ版の中身が違いうる。施主の判断は「揃えて」。`Release` ワークフローはタグでは起動しなくなり、手動の起動で実行の ID を渡すと、
その実行の成果物をそのまま出して、タグもワークフローが打つ。main で試し実行をして、通る側と落ちる側（main に載っていない実行）を測った。
**本当の公開は 1 度も動かしていない。**

### 3.4 スクリーンショット — 3 つの立場の批評で組み直した

最初の 1 枚目は時計を 10 個並べただけで、施主は「何だろう」と言った。Store の掲載・紙面の組み・書体と配色の 3 つの立場の役に批評させると、
共通して「端が揃っていない・主役が無い・地の色が中間で沈む・色が家族に見えない」が出た。段の高さを**余白の設定で**揃えて
（拡大・縮小せずに）左右の端を合わせ、配色をアプリ自身の色に絞って組み直した。施主の常用の配色（黒にワイン色）がコントラスト不足に
見えること、Playfair Display の 12 時間表記が「o7:44」に見えることは、この批評で初めて気付いた。
地の色（明るい石色）と、見出しの文字を入れないことは、施主が決めた。

### 3.5 撮ったら、版が違っていた（#130）

スクリーンショットの設定画面のフッターが「0.2.5」だった。`processResources` が埋める版を task の入力として宣言しておらず、
版だけを変えても UP-TO-DATE のままだった。配布物には出ていない（CI はまっさらな木から作る。v0.2.6 の zip の中は 0.2.6）。
**目で見なければ分からなかった。**

### 3.6 WACK（#121）

総合 WARNING。必須の検査は高 DPI の警告 1 件（Loupe と同じ）。任意の検査「ブロック済みの実行可能ファイル」が FAIL で、
中身は Java の実行環境とランチャーが持つ `CreateProcess` への参照と、圧縮された書体データの中の 3 文字の偶然の一致だった。
Microsoft の文書は、任意の検査は Store の評価に使わないと書いている。**審査に通るかは、申請するまで分からない。**
