## 今日やったこと

### 1. 出発点 — 外部 AI の草案と、施主の指定

施主が持ち込んだのは ChatGPT と作った `CLAUDE.md` / `SPECIFICATION.md` の草案。
指定は「これに加えて**これより優位に**、NENE2 / nene-recall / xi-tools / NeNeCommander / NENE-PIXEL の
コード規約にある『一つの事を実現するためには 1 つの方法を必ず取るようになる規約・ルール・CI』の思想に準拠して作る」。

草案の内容自体は妥当だったが、**ほぼ全部が「レビューで気をつけること」**だった。
「EDT で `Thread.sleep` しない」「UI から `Preferences` を直接触らない」「`LocalDateTime.now()` を散らさない」——
どれも正しいが、守られているかを確かめる手段が無い。**破っても何も起きない規約は必ず腐る。**

→ 草案は素材として全部取り込み、**規範としては ID 付きの機械強制体系へ書き換えた**（[ADR 0001](../adr/0001-strictness-is-mechanically-enforced.md)）。

### 2. 規範を書いた（71 規則・2,265 行）

先行 5 リポを読み、共通する中核 5 点を Java へ移した。

| --- | --- |

**すべての規則に「機械強制の状態」（active / planned / 不能 / 不採用）を持たせた。**
状態の正本は `docs/QUALITY_GATES.md` の強制マトリクス 1 か所で、
CNF-005 が「規範に定義があるのにマトリクスに行が無い」「未定義 ID を参照している」を拒否する。

### 6. 🔴 見つけたゲートの欠陥 4 件

**これが今日いちばん重要。** どれも「あると書いてあるのに効いていない」種類。

| # | 何が壊れていたか | なぜ気づけたか |
| --- | --- | --- |
| 1 | `determinism.txt` が**どのビルドからも読み込まれていなかった**。落ちて見えたのは bundled の `jdk-unsafe` が偶然拾っていたから。`System.nanoTime()` / `Instant.now()` は素通り | 次の作業の前に、別の API で発火を確かめ直した |

| 3 | 精密化 Kotlin script plugin が同一ソースセットの Java を解決できず、**fresh clone だと落ちる**。手元では過去の成果物が残っていて通っていた | コミットごとに `git worktree` で切り出して検証した |

### 7. 施主が実機で踏んだ不具合（#30）

表示が無い環境で `./gradlew run` すると、AWT のスタックトレース 20 行のあと **`BUILD SUCCESSFUL`・終了コード 0**。
例外が EDT 上で起きるため `main` が知らずに正常終了していた。**動かなかったのに成功として返る**形。

直す過程で規則の矛盾が出た。`base.txt` は `System.exit` を全モジュールで禁じていたが、
**その禁止理由には「プロセスを終わらせる判断は合成ルートの責務」と書いてあった。**
規則が自分の理由と矛盾していたので、[ADR 0005](../adr/0005-composition-root-owns-the-terminal.md) で合成ルートへ寄せた。

## 判断の要点

- **規則が自分の理由と矛盾していた例が 2 件**（`System.exit` の禁止範囲・ARC-005 と設定の所有者）。
  どちらも「要件が来て初めて」露見した。**規約は使われるまで正しさが試されない。**
- **negative proof は「落ちること」ではなく「何によって落ちたか」まで見る。**
  別の道具がたまたま拾っているだけの状態を「このゲートが効いている」と誤読する。
  出力は必ず実行結果から引用する（記憶で書かない）
- **テストも「正しい理由で落ちているか」まで見る。** CNF-002 のテストは
  別の理由で拒否されていたので通っていた。規則 ID しか見ていなかった
- **手元が緑でも、クローンした人の手元が緑とは限らない。** コミットごとに `git worktree` で検証する
- 例外区画（「ここだけ許す」モジュール）は 3 つになった。**増えたこと自体を ADR に書いて警告に使う**
