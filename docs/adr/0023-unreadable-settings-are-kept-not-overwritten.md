# ADR 0023 — 読めなかった設定は上書きしない。未来の版は読み取り専用、壊れた値は退避してから保存する

- 状態: 受理
- 日付: 2026-10-18
- Issue: #150
- 影響する規則: ARC-002 / ARC-009 / ARC-010 / FR-042 / FR-045。ADR 0003 の却下表の最後の行と、合成ルートの食い違いを解く

## 文脈

設定を読めなかったとき（`SettingsLoadOutcome.Defaulted`）、`SettingsHandler.restoredFrom` は既定値で始め、そのことをどこにも伝えない。
次に 1 項目でも変えると、`save` は読めなかった設定を**現在の版で上書きする**。

- 未来の版（新しい版で保存した設定を古いアプリで開いた）: 版を戻しただけで設定が消える
- 壊れた値（`INVALID_VALUE`）: 元の値が残らない
- ADR 0003 の却下表は「移行できない版を黙って既定値にする」を退けているのに、合成ルートは黙って既定値にしている

施主の判断（2026-10-15・Issue #150）: **版で分ける。ADR を書いてから実装する。**
hub 経由で届いた「両方とも読み取り専用」は、壊れた値に当てると一度壊れた利用者が二度と保存できなくなる（次の起動でも読めない）ので、施主に直接聞いて改めた。

## 決定

**読めなかった理由で分け、保存形式を持つ `PreferencesSettingsAdapter.save` が判断する。読み込みの結果は設定画面のフッターで伝える。**

| 読めなかった理由 | `save` の動き | 伝え方 |
| --- | --- | --- |
| 未来の版（`UNSUPPORTED_SCHEMA`） | 書かない。`Failed(NEWER_VERSION_KEPT)` を返す（読み取り専用） | 起動時から「新しい版の設定を守るため、変更は保存しません」 |
| 壊れた値（`INVALID_VALUE`）・読めない（`UNREADABLE`） | 元のキーを子ノード `unreadable-backup` へ写してから、現在の版で書く | 起動時に「設定を読めず既定値で始めました。元の値は残しています」 |
| 初回（`ABSENT`） | いまのまま書く | いまのまま |

1. `save` は書く前に保存領域を読み直して判断する（`load()` の結果を使う）。`load()` は今まで通り保存領域を書き換えない（ADR 0003）。退避は最初の保存のときに行う
2. 版が 1 未満（0 以外）の値と、整数として読めない版の値は、未来の版ではないので壊れた値（`INVALID_VALUE`）として扱う。いままでは前者を `UNSUPPORTED_SCHEMA`、後者を初回（`ABSENT`）と同じに扱い、黙って上書きしていた
3. 退避先は 1 つ。もう一度壊れたら、前の退避を新しい退避で置き換える
4. 読み込みの結果は `SettingsHandler.restoration()` が持ち、合成ルートが起動時に設定画面へ渡す。保存の失敗の理由に `NEWER_VERSION_KEPT` を足し、`SettingsDialog.describe` の網羅の switch が置き場を示す（JAV-002）

## 強制

- **active**: adapter の単体テスト（未来の版の上で保存しても保存領域が変わらない・壊れた値の上で保存すると元の値が退避先に残り、本体は現在の版になる・版 0 未満と数でない版は `INVALID_VALUE`・退避の後は普通に保存できる）、application の単体テスト（`restoration()` が読み込みの結果を返す）
- **planned**: 設定画面の文言の目視（`./gradlew run`・CLAUDE.md 第 3 節）

## 結果

- 版を戻しても、新しい版の設定は消えない。古いアプリでは変更が保存されないことが画面に出る
- 壊れた設定の利用者は、元の値を残したまま保存を再開できる
- 保存のたびに保存領域を 1 回読み直す（Preferences はメモリに持っているので、読み直しは書き込みより軽い。#143 の計測で見る）
- 退避先が保存領域に 1 つ増える。中身は元のキーそのままで、アプリは読まない

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| どちらも読み取り専用にする | 壊れた値の利用者が二度と保存できなくなる（施主に確かめて改めた） |
| `load()` の中で退避する | 読み取りが副作用を持つ（ADR 0003 の却下理由と同じ） |
| 判断を application に置く | 保存形式と版を知るのは adapter の責務（ARC-002・ADR 0003） |
| 未来の版を推測して読む | 読めないものは読めないと返す（ADR 0003） |
| 黙ったまま既定値で動く | ARC-009 が禁じる挙動そのもの |
