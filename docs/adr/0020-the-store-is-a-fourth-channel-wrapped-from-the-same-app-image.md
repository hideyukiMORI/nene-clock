# ADR 0020 — Microsoft Store を 4 つ目の配布経路にする。同じ app-image を MSIX に包む

- 状態: 受理
- 日付: 2026-10-04
- Issue: #107
- 影響する規則: QLT-001 / QLT-005 / ARC-012 / ADR 0013 / ADR 0014 / ADR 0015

> **2026-10-04 に施主が受理した。** 根拠は下調べの報告（[2026-10-04-store-msix-research](../reports/2026-10-04-store-msix-research.md)）。
> 実装は #116〜#122 で進める。版を上げるのは、施主が「上げる」と言ってから（#119）。

## 文脈

ADR 0013 は MSIX / winget / Microsoft Store を「署名が前提。署名しないと決めたので採れない」として却下した。
**この理由は Store 配布については成り立たない。** Store に MSIX で出すと、認定のあとに Store が Microsoft の証明書で
署名し直す。自前の証明書は要らない。個人の開発者登録は無料で、施主の登録と本人確認は済んでいる。
一次資料での裏取りは NeNe Loupe が行い（同リポの `docs/reports/2026-10-03-store-msix-research.md`）、
Loupe 1.0.0 は 2026-10-04 にその経路で公開された。Clock では調べ直していない。

ADR 0013 が「失うもの」に挙げた **SmartScreen の警告は、Store から入れた場合には出ない**（同上）。
署名しない方針（施主決定 2026-09-04）を変えずに、警告の出ない入口を 1 つ持てることになる。

Clock に固有の未確認は 3 点あり、2026-10-04 に実測した（報告の A 節）。

| 点 | 結果 |
| --- | --- |
| jpackage の app-image を MSIX に包めるか | **包めた。** 配布済みの v0.2.6 の app-image（148 ファイル）をそのまま `makeappx` に渡して 32 MB の MSIX になった。読み取り専用の `C:\Program Files\WindowsApps\` に入れた状態で、パッケージの身元を持って起動し、同梱書体で描かれた。製品コードは変えていない |
| `java.util.prefs`（HKCU）の行き先 | **読むときは本物のレジストリが見える。書くときはパッケージ専用の場所へ行き、本物は変わらない。** MSI 版の設定は引き継がれるが、書き戻されない |
| CI の Windows ランナーで作れるか | **作れた。** `windows-2025` のランナーに Windows SDK 10.0.26100.0 の `makeappx` / `makepri` があり、`packageInstaller` が作った app-image をそのまま包めた。PATH には無いので、場所は task が決める |

## 決定

1. **Store（MSIX）を 4 つ目の配布経路として足す。** MSI・ポータブル zip・`.deb` は残す。Store は入口を増やすもので、置き換えではない
2. **MSIX の入力は `packageInstaller` が作った app-image だけにする。** MSIX のために jar も実行環境も作り直さない。
   zip と MSI と MSIX は同じ app-image から出る（ADR 0013 の決定 3 / ADR 0014 と同じ原則）
3. **手順は Gradle task に閉じる**（QLT-005）。ワークフローはその task を呼び、できたものを置くだけにする。
   `makeappx` / `makepri` は Windows SDK の道具なので、task は Windows でだけ MSIX を作る（MSI と同じ扱い）
4. **版は `gradle.properties` の 1 か所のまま。** MSIX の版はそこから `X.Y.Z.0` を作る。MSIX だけ別の版にしない。
   Store は先頭が 0 の版を受け付けないので、**出すなら 1.0.0 以上へ上げる**（上げるのは施主が決めてから）
5. **パッケージの身元（`Identity/Name`・`Publisher`・`PublisherDisplayName`）は Partner Center が示す値を 1 つのファイルに置く。**
   手元の検証用の身元とは別にし、提出用は署名しない（Store が署名する）
6. **ロゴは `AppIcon` から書き出す**（ADR 0013 の決定 5 と同じ原則）。絵を手で別に持たない
7. **設定の保存先は変えない。** `java.util.prefs` のまま包む。Store 版の設定がパッケージ専用の場所に入ることは README に書く
8. **鍵と証明書をリポジトリに入れない。** 手元の検証は、開発者モードでの登録か、証明書ストアの中だけに置く持ち出し不可の鍵で行う

## 強制

- **planned**: MSIX を作る Gradle task（決定 2〜4）。実装する Issue で入れる。入るまでは何も強制されていない
- **planned**: 「MSIX の中の app-image が、zip の中身と同じである」ことの検査。Loupe は exe の SHA-256 を突き合わせている。
  Clock はファイルが 148 あるので、突き合わせ方（全ファイルか、jar と launcher か）を実装のときに決める
- **不能**: Store の認定に通ること。申請しないと分からない。Windows App Certification Kit は申請の前に通すが、ゲートには入れない
  （管理者権限でアプリを何度も起動する検査で、CI では回せない）

## 結果

得られるもの:

- SmartScreen の警告が出ない入口。更新は Store が配る
- 署名しない方針のまま、署名された配布物を 1 つ持てる

失うもの・増えるもの:

- **設定の場所が、入れ方によって 2 つになる。** MSI 版と zip 版は `HKCU\Software\JavaSoft\Prefs`、Store 版はパッケージ専用の場所。
  MSI 版から乗り換えた人は設定を引き継ぐが、Store 版で設定を変えたあとは別々になる（報告の A-2）
- プライバシーポリシー・掲載文・スクリーンショット・ロゴ一式という、製品の外の成果物が増える
- 版の番号に Store の制約（先頭は 0 にできない・4 番目は 0）が掛かる
- 配布経路が 4 つになる。入口は `packageInstaller` 1 つのままにして、経路ごとの手順を増やさない

移行に要る作業は #116（MSIX の task）・#117（ロゴと `resources.pri`）・#118（`PRIVACY.md`）・#119（版）・#120（掲載文と画像）・#121（WACK）・#122（README）。

## ADR 0013 への訂正

ADR 0013 の「却下した選択肢」のうち、次の 1 行は理由が誤っていた。

> MSIX / winget / Microsoft Store | 署名が前提。署名しないと決めたので採れない

正しくは次のとおりである。

| 経路 | 自前の署名 |
| --- | --- |
| Store に MSIX で出す | **要らない。** Store が署名し直す |
| Store に MSI / EXE で出す | 要る |
| Store の外で MSIX を配る | 要る（自己署名では、利用者が管理者権限で証明書を入れることになる） |
| winget に MSIX を出す | 要る |

受理に伴い、ADR 0013 のその行にここへの参照を足した。ADR 0013 のほかの決定（MSI で配る・署名しない）は変わらない。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| MSI を Store に出す | 自前の署名と、版ごとの HTTPS でのホスティングが要る。署名しない方針と合わない |
| MSIX のために別のビルドを作る（Store 用の jlink・Store 用の jar） | 配る中身が経路ごとに別物になる。同じ app-image を包めることは実測で分かっている |
| 設定の保存先をファイルへ変えて、Store 版でも同じ場所に書かせる | 製品の振る舞いの変更であり、MSI 版の利用者の設定の移行が要る。包んだままで読めて書けるので、変える理由が無い |
| MSI・zip をやめて Store だけにする | GitHub から直に入れたい人と、Store を使えない環境の入口が無くなる |
| ワークフローの中で `makeappx` を直接叩く | 手順が CI 専用になり、手元で再現できない（QLT-005・ADR 0013 と同じ理由） |
