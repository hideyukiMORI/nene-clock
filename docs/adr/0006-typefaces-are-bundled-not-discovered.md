# ADR 0006 — 書体は同梱する。実行環境からは読まない

- 状態: 受理
- 日付: 2026-09-04
- Issue: #34
- 影響する規則: ARC-001 / ARC-002 / ARC-003 / ARC-007 / FR-042 / FR-043 / JAV-002 / JAV-007

## 文脈

M0.1 までの実装は、設定画面に並べる書体を `GraphicsEnvironment` から読んでいた。
FR-043 はそれを「利用可能性は環境依存の事実であり、保存値の不変条件ではない」と正しく整理していたが、
利用者から見た結果は次のとおりだった。

- 同じ設定でも PC が変われば別の書体で描かれる
- 素の Linux では論理フォント数種しか出ず、「雰囲気を選ぶ」体験が成立しない
- この 1 モジュールのために `config/forbiddenapis/platform.txt` の適用除外（例外区画）が 1 つ必要だった

施主要件は「OS の書体ではなく、Google Fonts の人気書体を 30 種類ほどから選ばせたい」である。

## 決定

**30 書体（SIL Open Font License）の TrueType ファイルをリポジトリに同梱し、そこからしか選べないようにする。**

- 書体は `Typeface` 列挙になる。**保存されるのは列挙の定数名**であって、環境の書体名ではない
- 実体（TTF）を持つのは `:adapters:font-catalog` ただ 1 つ。application へは
  `TypefaceBinaryPort` がバイト列で渡し、`java.awt.Font` への変換は UI が行う（ARC-003）
- ファイルは**無改変**で同梱する。上流（`google/fonts`）の commit と SHA-256 を
  `typefaces/provenance.tsv` に記録し、**テストが実体と突き合わせる**
- 各書体の OFL 本文を同じ場所に同梱する
- 資源名は定数名から機械的に導出する（`DM_SANS` → `dm-sans.ttf`）。人が書く対応表を作らない
- 実行環境へ書体を**登録しない**（`GraphicsEnvironment#registerFont` を使わない）。
  登録すると「名前で引く」経路が生まれ、書体の指定経路が 2 本になる（ARC-001）

### 帰結として起きる 3 つの単純化

1. **`FontFamily` / `FontFamilyOutcome` / `FontFamilyRejection` が消える。**
   任意の文字列を検証して受け入れる必要が無くなり、閉じた選択肢は列挙で表せる（JAV-002）
2. **`FontCatalogPort` と `SettingsView` が消える。** 「選べるもの」は domain が知っているので、
   一覧を application 経由で UI へ運ぶ必要が無い
3. **例外区画が 3 つから 2 つに減る。** `platform.txt` を外すモジュールが 0 になった

## 強制

- **active**: 全 30 定数について、同梱ファイルが存在し `Font.createFont` が成功することを
  `:adapters:font-catalog:test` が見る（「ファイルがある」で止めない）
- **active**: 記録された SHA-256 が実体と一致することを同モジュールのテストが見る。
  ファイルを差し替えて記録を直し忘れても、記録だけ書き換えても落ちる
- **active**: 全 30 定数について OFL 本文が同梱されていることを見る
- **active**: `platform.txt` はすべてのモジュールに適用される。
  `GraphicsEnvironment` を書けば、どのモジュールでもビルドが落ちる
- **planned**: 「同梱ファイルはあるが列挙に無い」（余ったファイル）の検出。
  いまは資源名の導出が唯一の経路なので、余っても描画には影響しない

## 保存形式の移行（v2 → v3）

v2 は実行環境の書体名を文字列で持っている。その名前は同梱書体の集合とは別物である。

- **同じ名前の同梱書体があれば、その選択は生きていたとみなして引き継ぐ**（例: `Inter`）
- 無ければ**書体だけ**既定へ落とす。ほかの 6 項目は保つ
- 元の名前を保ったまま持ち回らない。描かれない書体名が設定の中に残り続けるのを避ける

## 結果

得られるもの:

- どの PC でも同じ見た目になる。スクリーンショットと実物が一致する
- 「雰囲気で選ぶ」体験が成立する（30 書体・6 分類）
- 例外区画が 1 つ減り、規約が 1 つ単純になった
- 書体の選択肢が閉じたので、UI は一覧を受け取らずに描ける

失うもの:

- **リポジトリが約 7 MB 重くなる**（30 ファイル）。書体の追加はリポジトリの成長を意味する
- 利用者が自分の好きな書体（社内フォント等）を使えない。
  これは「どの環境でも同じ見た目」と両立しない要求であり、意図的に捨てる
- 上流が書体を更新しても自動では追随しない。追随は明示的な更新作業になる

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 実行環境の書体一覧を読み続ける（現状維持） | 施主要件を満たさない。同じ設定で同じ見た目にならない問題も残る |
| 同梱書体と実行環境の書体の**両方**から選べるようにする | 書体の指定経路が 2 本になる（ARC-001）。「この設定はどちらの世界の名前か」を保存値が持たねばならず、FR-042 の失敗の種類が増える |
| ビルド時に Google Fonts からダウンロードする | オフラインでビルドできなくなる。`kit=` 付きの配信 URL は不安定で、出所を固定できない |
| フォントを latin へサブセットして小さくする | 改変になる。OFL の Reserved Font Name 条項に触れる書体があり、書体ごとに可否を判定する義務が生じる。7 MB のほうが安い |
| `GraphicsEnvironment#registerFont` で登録し、名前で引く | 「名前で引く」経路が復活する。同梱したのに環境依存の名前解決に戻る |
| 資源名を列挙に第 3 引数として書く | 表と実体がずれても気づけない。導出なら「定数はあるがファイルが無い」形でしかずれられず、それは必ず落ちる |
