# ADR 0001 — 厳格さは機械で強制する

- 状態: 受理
- 日付: 2026-09-03
- Issue: #1
- 影響する規則: すべて

## 文脈

本リポジトリの規約は、先行する 4 リポジトリ（NENE-PIXEL＝Kotlin / NeNeCommander＝C# /
nene-recall＝Go / xi-tools＝Rust）で確立された考え方を Java へ持ち込んだものである。
そこで共通していた中核は 1 つに要約できる。

> **一つのことを実現する方法を 1 つに固定し、そのことを人の記憶ではなく機械に守らせる。**

このプロジェクトには、元になった別案（外部の AI と作成した実装方針書）があった。
内容は妥当だったが、**ほぼすべてが「レビューで気をつけること」だった**。
「`Thread.sleep` を EDT で呼ばない」「UI から `Preferences` を直接触らない」「`LocalDateTime.now()` を
散らさない」——どれも正しいが、守られているかどうかを確かめる手段が無い。
規約は、破ったときに何も起きなければ、時間とともに必ず腐る。

## 決定

**すべての規範規則に「機械強制の状態」を持たせ、その状態を文書の側で機械検査する。**

- 状態は `active` / `planned` / `不能` / `不採用` の 4 つ
- 正本は `docs/QUALITY_GATES.md` の強制マトリクス
- `validateConformance`（CNF-005）が、「規範文書に定義があるのにマトリクスに行が無い」
  「未定義の規則 ID を参照している」を拒否する
- ゲートは 1 つ（`./gradlew check`）。CI は同じタスクを呼ぶだけにする（QLT-001）
- baseline を持たない（QLT-003）。例外は期限付きの狭い waiver だけ
- 自作ゲートは negative proof がそろうまで信用しない（QLT-007）

## 強制

- **active**: CNF-005（文書整合）・CNF-008（baseline 禁止）・CNF-009（waiver 期限）
- **不能**: 「`planned` を勝手に `active` と書き換えないこと」そのもの。
  マトリクスの行と実装の対応は、いまは人が見るしかない

## 結果

得られるもの:

- 規約が自分について嘘をつく経路が塞がる
- 新しい貢献者（人でも AI でも）が「何がいま守られているか」を 1 か所で読める
- 規約を緩めるコストが上がる（QLT-010）

失うもの:

- 文書のメンテナンスコスト。規則を足すたびに 3 か所（本文・マトリクス・実装）が同期を要求される
- 検査の実装そのものの保守（`build-logic` の Java コードとその単体テスト）

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 散文の規約だけを置く（元の実装方針書の形） | 守られているかを確かめる手段が無く、時間とともに必ず腐る。**本 ADR の出発点そのもの** |
| Checkstyle / PMD / SpotBugs の既製ルールだけで済ませる | 既製ルールは「Java として危ういこと」を見るが、「NeNe Clock として守るべきこと」（時刻の入手経路が 1 本か、UI 状態の反映が 1 か所か）は見られない |
| `@SuppressWarnings` を全面禁止する | 機械で禁止できない（Java に `forbid` 相当が無い）。禁止と書くと**守られていない規則が 1 つ増えるだけ**になる。waiver 台帳（CNF-002 / CNF-009）で補う |
| baseline を作って既存違反を後回しにする | 新規リポジトリなので既存違反が無い。ここで baseline を許すと、以後の違反も同じ入口から入ってくる（QLT-003） |
| 規則 ID を付けず散文で参照する | 「どの規則の話か」がレビューのたびに揺れる。ID があると tooling・ADR・PR・waiver が同じ語を指せる |
