# ADR 0005 — 端末とプロセス終了コードは合成ルートが持つ

- 状態: 受理
- 日付: 2026-09-03
- Issue: #30
- 影響する規則: ARC-006 / ARC-010 / QLT-010 / QLT-012 / FR-030

## 文脈

表示（X11 / Wayland）が無い環境で起動すると、AWT のスタックトレースが 20 行ほど出たうえで
**`BUILD SUCCESSFUL`・終了コード 0** になっていた。例外が EDT 上で起きるため `main` は
何も知らずに正常終了する。**動かなかったのに成功として返る**形であり、
QLT-012（環境依存の主張は正直に名付ける）が最も嫌う状態である。

直すには 2 つが要る。**失敗を `main` まで持ち帰ること**と、**利用者に伝えること**。
前者は `invokeAndWait` で済む。後者が問題で、窓が出る前に届く経路は端末しか無い。

しかし現在の規則は、端末もプロセス終了も**全モジュールで禁止**していた。

- `System.exit` は `config/forbiddenapis/base.txt` が禁止。
  🔑 **ところがその禁止理由には「プロセスを終わらせる判断は合成ルートの責務」と書いてあった。**
  合成ルートでも禁止していたので、規則が自分の理由と矛盾していた
- 標準出力・標準エラーは bundled signature の `jdk-system-out` と ArchUnit が禁止

## 決定

**`:app`（合成ルート）だけが、端末への出力とプロセスの終了コードを扱ってよい。**

- `System.exit` 系を `base.txt` から `process-control.txt` へ分離し、`:app` 以外へ適用する
- `:app` は bundled signature から `jdk-system-out` を外す
- ArchUnit の標準ストリーム規則を「`:app` の外では禁止」に絞り、理由に本 ADR を書く
- 出せるのは **起動できなかった理由 1 行**だけ。スタックトレースは見せない（FR-030）
- ログ出力の手段として使わない。動いているアプリは端末に何も書かない

除外は `app/build.gradle.kts` の差分として見える形で置く。既存の 2 つの例外区画
（`:adapters:system-time` の時刻、`:adapters:font-catalog` の書体一覧）と同じ形である。

## 強制

- **active**: `:app` 以外で `System.out` / `System.err` に触ると forbidden-apis が拒否する
  （実測: `Forbidden field access: java.lang.System#err`）
- **active**: 同じ違反を ArchUnit も拒否する（実測: `Architecture Violation ... should access standard streams`）
- **active**: `:app` 以外で `System.exit` を呼ぶと forbidden-apis が拒否する
- **不能**: 「端末への出力が 1 行に収まっているか」「ログとして使っていないか」。レビュー事項

## 結果

得られるもの:

- 起動できなかったことが、利用者に読める形で、正しい終了コードとともに伝わる
- 規則が自分の理由（「合成ルートの責務」）と一致した

失うもの:

- 例外区画が 3 つ目になった。区画が増えるほど「唯一の窓口」という説明は弱くなる。
  4 つ目を作るときは、本当に他の層で不可能かを本 ADR と同じ形で問い直すこと
- `:app` は bundled signature の集合が他モジュールと違う。ビルドファイルを読まないと分からない

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 何もしない（現状維持） | 失敗が成功として返る。自動化から見ると「動いた」と区別できない |
| `main` から意味のある例外を投げるだけ | 終了コードは 1 になるが、スタックトレースは残る。FR-030 と食い違う。また「期待される環境条件」を例外で表すことになり JAV-005 と擦れる |
| ログライブラリを入れる | 依存が増える。0.1 系は JDK 以外の実行時依存を持たない方針（DEVELOPMENT_WORKFLOW の依存の方針） |
| ダイアログ（`JOptionPane`）で伝える | 表示が無いから失敗しているので、ダイアログも出せない |
| 起動前に `GraphicsEnvironment.isHeadless()` で判定する | 「実行環境を覗く窓口は `:adapters:font-catalog` だけ」という説明に穴を開ける。実際に失敗したものを捕まえるほうが、条件を先読みするより正確でもある |
| 全モジュールで端末を許す | ログ代わりの `println` が全層に散る。いま無い問題をわざわざ作る |
