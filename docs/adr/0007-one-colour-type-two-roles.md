# ADR 0007 — 色の型は 1 つにし、役割は成分名で語る

- 状態: 受理
- 日付: 2026-09-04
- Issue: #35
- 影響する規則: ARC-004 / ARC-009 / FR-044 / FR-046 / JAV-001 / JAV-007 / QLT-010

## 文脈

施主要件により背景色を設定できるようにする。FR-044 は「背景色は設定対象外である」と
明記していたので、**仕様の判断を覆す変更**である（枠なしウィンドウ（#36）では窓そのものが
色面になるため、背景色は装飾ではなく主要な設定になる）。

文字色は `FontColor`（RGB 3 成分・0..255・透明度なし）として既にある。
背景色は**値の規則が文字色と完全に同じ**である。ここで型をどう置くかに 2 つの道がある。

1. `FontColor` と `BackgroundColor` を別の型にする（取り違えをコンパイラが止める）
2. 色の型を 1 つにし、どちらであるかは `UserSettings` の成分名で語る

1 は魅力的である。`UserSettings` の成分に同じ型が 2 つ並ぶと、組み立てのときに
引数を取り違えても**コンパイルが通ってしまう**（黒地に黒で起動する）。
このリポジトリの原則からすれば、機械に止めさせたい種類の誤りである。

しかし 1 を採ると、**「各成分が 0..255」という 1 つの規則が 2 つの型に写る**。
規則の重複はこのリポジトリが最も嫌う形であり（ARC-001 / QLT-010）、
片方だけを直しても誰も気づかない経路をつくる。

## 決定

**色の型を `RgbColor` 1 つにする。文字色か背景色かは `UserSettings` の成分名が語る。**

- `FontColor` / `FontColorOutcome` / `FontColorRejection` を
  `RgbColor` / `RgbColorOutcome` / `RgbColorRejection` へ改名する
- 既定値は `RgbColor.DEFAULT_FONT`（`#000000`）と `RgbColor.DEFAULT_BACKGROUND`（`#F5F2EB`）。
  非公開コンストラクタで組み立てるため、既定値は型の中に置く（`FontSize.DEFAULT` と同じ形）
- 表示に関する事実の所有者は `UserSettings` ただ 1 つである（ARC-004）。
  「どちらの色か」もその所有者が持つ事実であって、色の値そのものの性質ではない

## 強制

- **active**: 保存と復元で文字色と背景色が入れ替わらないことを
  `:adapters:preferences` のテストが見る（両方に別の値を入れて往復させる）
- **active**: 既定の 2 色が互いに読める関係にあることを `:core:domain` のテストが見る
- **planned**: 組み立て時の取り違えの検出。型では止められないので、
  取り違えたときに落ちるテストを置くことでしか防げていない。
  **これは「機械で止めた」ではない。止められていないことを、ここに書いて残す**

## コントラストの扱い

読めない組み合わせ（黒地に黒）を**禁止しない**。

- 設定は利用者のものであり、アプリが勝手に上書きしない
- 代わりに設定画面が警告し、読める色への修正を 1 操作で提案する（#36）
- 「禁止」にすると、どこまでを禁止とするかの閾値をアプリが決めることになる。
  その閾値は利用者の視力・画面・環境光を知らないまま決めた数字にしかならない

## 結果

得られるもの:

- 色の規則が 1 か所にある。範囲を変えるなら 1 か所を直せばよい
- 型が 2 つ減った状態で機能が 1 つ増えた

失うもの:

- **文字色と背景色の取り違えをコンパイラが止められない。** テストでしか守られていない
- `RgbColor` が `DEFAULT_FONT` / `DEFAULT_BACKGROUND` という役割つきの定数を持つ。
  値の型が用途を少しだけ知っている状態であり、きれいではない

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| `FontColor` と `BackgroundColor` を別の型にする | 同じ不変条件が 2 か所に写る。片方だけ直しても誰も気づかない。取り違えを止める価値より、規則の重複の害が大きいと判断した |
| `RgbColor` を共有し、その上に薄い 2 つの型をかぶせる | 型が 3 つになる。得られる安全は「別の型にする」と同じで、複雑さだけが増える |
| 文字色と背景色を 1 つの「配色」型にまとめて `UserSettings` へ 1 成分で渡す | 取り違えの場所が `UserSettings` から配色型の生成箇所へ移るだけで、無くならない |
| 読めない組み合わせを拒否する | 閾値をアプリが決めることになる。利用者の設定をアプリが上書きする形にもなる |
| 版を上げずに背景色のキーを足す | 「v3 なので欠けている」と「v4 なのに壊れている」を区別できなくなる（ADR 0003 と同じ理由） |
