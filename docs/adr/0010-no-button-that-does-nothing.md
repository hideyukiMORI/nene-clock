# ADR 0010 — 押しても何も起きないボタンを置かない（移動アイコンをやめる）

- 状態: 受理
- 日付: 2026-09-04
- Issue: #48
- 影響する規則: FR-047 / ARC-011 / JAV-002
- 関係: [ADR 0008](0008-the-window-is-the-clock.md) の判断を一部改める

## 文脈

ADR 0008 は、枠なし窓のクロームに 3 つのアイコン（移動 / 設定 / 終了）を置くと決めた。
移動アイコンについてはこう書いた。

> **窓のどこを掴んでもドラッグで動く。** 移動アイコンは「掴める」ことを教える役目である

施主の指摘: **どこを掴んでも動くなら、その矢印は要らない。**

改めて見ると、その理屈は 2 つを見落としていた。

1. 窓のどこを掴んでも動くのは、枠なし窓では当たり前の作法である。教える必要が薄い
2. **押しても何も起きないボタンを画面に置いていた。** 実装にもそれが現れていて、
   `ClockScreen#actOn` に「MOVE のときは何もしない」という分岐が存在した。
   コードが「この要素には意味が無い」と言っていたのに、画面からは外さなかった

🔑 **アイコンが 3 つ並べば、利用者は「押せるものが 3 つある」と読む。**
そのうち 1 つが無反応なら、それは説明ではなく嘘である。

## 決定

**移動アイコンを置かない。** クロームは設定（ギア）と終了（×）の 2 つにする。

- 窓のどこを掴んでも動く挙動は**変えない**
- `ChromeIcon` から `MOVE` を削る。網羅性の検査（JAV-002）が分岐の消し忘れを拒否する
- レールが 1 つぶん狭くなり、時計の上に載る面積が減る

## 強制

- **active**: `switch` の網羅性（コンパイラ）。定数を削ると、扱っていた分岐が残っていれば落ちる
- **planned**: 「押しても何も起きない要素」の一般的な検出。
  今回は分岐に「何もしない」と書いてあったので**読めば分かった**。読まなかっただけである

## 結果

得られるもの:

- 画面の要素がすべて意味を持つ
- 「何もしない」分岐が消えた

失うもの:

- 窓を動かせることが、見ただけでは分からない。**掴んでみるまで分からない**

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 移動アイコンを残し、押したら窓が中央へ戻るようにする | 「移動」の見た目に対して別の動作を割り当てることになる。嘘が別の嘘に変わるだけ |
| 移動アイコンだけドラッグの取っ手として機能させる | 掴める場所が 32px 四方に狭まる。ADR 0008 で却下済みの案に戻る |
| アイコンを残して無効に見せる（薄く描く） | 使えない要素を画面に置き続けることに変わりはない |
