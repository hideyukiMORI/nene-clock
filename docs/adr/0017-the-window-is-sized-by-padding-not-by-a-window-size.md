# ADR 0017 — 窓の大きさは「余白」で変える。窓サイズという設定は持たない

- 状態: 受理
- 日付: 2026-09-22
- Issue: #94
- 影響する規則: FR-040 / FR-045 / ARC-009 / JAV-007 / CNF-004
- 関係: [ADR 0008](0008-the-window-is-the-clock.md) の「幅は起こりうる最も広い文字列で決める」を**精密化する**（置換ではない）

## 文脈

施主要件:「フォントサイズの変更はいい感じ。でも**窓の大きさを変えられない**。パディングか窓サイズか、
適切なほうで変えられるようにしたい」。

いまの大きさは 1 本の経路で決まっている（`ui/swing/.../ClockPanel.java:112-118`）。

```java
int width  = Math.max(timeMetrics.stringWidth(WIDEST_TIME), dateMetrics.stringWidth(WIDEST_DATE));
int height = timeMetrics.getHeight() + LINE_GAP + dateMetrics.getHeight();
return new Dimension(width + PADDING * 2, height + PADDING * 2);
```

`PADDING = 30` は固定の定数であり、利用者は触れない。そして `WIDEST_TIME` は **`"00:00:00 AM"` 固定**である。

🔑 **ここに 2 つ別の問題がある。**

1. 余白を変える手段が無い（＝施主の要件そのもの）
2. **設定で表示を減らしても窓が縮まない。** 24 時間表示にしても、秒を隠しても、日付を隠しても、
   幅は常に「12 時間表示・秒あり・AM/PM つき」の幅で確保される。
   ⇒ 「窓が無駄に広い」という体感の一部は、余白ではなく**この計算**が作っている

## 決定

**余白（padding）を設定項目にする。窓の大きさそのものは設定にしない。
そして幅・高さは「いまの設定で起こりうる最大」ちょうどにする。**

- 窓の大きさは、これまでどおり **導かれる値**である: `書体 × 文字サイズ × 表示内容 × 余白 → 窓の大きさ`
- 「起こりうる最大」の意味を「どの設定でも起こりうる最大」から **「この設定で起こりうる最大」** へ狭める。
  毎秒・毎分で窓が震えないこと（ADR 0008:33-34 の要求）は維持する — 数字の字幅差と AM/PM の差を
  あらかじめ含めた最大で測るからである

### なぜ「窓サイズ」を設定にしないか

文字サイズと窓サイズの**両方が大きさを主張すると、どちらかが必ず折れる**。

| 折れ方 | 起きること |
| --- | --- |
| 窓が勝つ | 時刻が `05:14:..` と切れる（2026-09-04 に実機で踏んだ・gate-proofs §11:350） |
| 文字が勝つ | 利用者が選んだ文字サイズが、窓の都合で勝手に変わる |

ADR 0008:87 が「窓の端でリサイズできるようにする」を却下したのと同じ理由である。
**余白なら、どちらも折れない。** 文字は利用者の指定どおりに描かれ、窓はそれを包む量だけ変わる。

### 「最大」は 1 本の文字列ではない

⚠️ ここを 1 本の文字列と読むと実装できない。**どの数字が最も広いか・AM と PM のどちらが広いかは、
書体を見ないと決まらない。** そして書体の送り幅を知れるのは `:ui:swing` だけである（ARC-003）。

だから **application 層は「起こりうる面の候補」を渡し、UI はそれを測って最大を取る**。
UI 側に `WIDEST_TIME = "00:00:00 AM"` のような定数を置き直さない（置いた瞬間、整形の知識が 2 か所になる）。

## 強制

- **active**: `:core:domain` の値型（範囲外の余白は作れない。JAV-007 の「非公開コンストラクタ＋唯一のファクトリ」）
- **active**: 保存形式 v7 → v8 の移行テスト（v7 には余白が無いので既定値を埋める。ARC-009）
- **active**: 反映は `render` で始まるメソッドの中だけ（CNF-004）
- **不能**: 「窓が実際に狭くなったか」「毎秒震えないか」は**見た目**であり、機械検査できない。
  `./gradlew run` で目視し、[quality/gate-proofs.md](../quality/gate-proofs.md) に記録する（QLT-012）

## 結果

得られるもの:

- 窓の大きさを利用者が変えられる（要件）
- 設定で表示を減らすと**実際に窓が縮む**。「24 時間表示にしたのに AM/PM の幅が残っている」が消える
- 大きさの決まり方は 1 本のまま。新しい経路を作っていない

失うもの・代償:

- 🔴 保存形式が v8 になる。移行は v1〜v7 から。**既存の設定を失わないことをテストで示す**
- 🔴 `UserSettings` の成分が 1 つ増えるので、`withXxx` と全テストの `new UserSettings(...)` が機械的に膨らむ
- 幅の計算が「いまの設定」に依存するようになるため、**設定を変えたときに幅を計算し直す責任**が増える
  （`renderSettings` の中で行う。CNF-004 の経路から外さない）
- 🔴 **最小サイズ 320×160 との相互作用が残る。** 下限は**広げる向きにしか効かない**ので文字は切れない。
  ただし小さい設定（文字が小さい・秒や日付を隠している）では、自然な大きさが下限を下回るため、
  **余白を増やしても窓が動かない区間ができる**。本 ADR の決定範囲外として下限は触っていない（Issue #97）

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 窓の幅・高さを直接の設定にする | 上表のとおり、文字サイズと衝突して必ずどちらかが折れる。ADR 0008:87 と同じ理由 |
| 窓の端を掴んでリサイズできるようにする | ADR 0008 で却下済み。枠の無い窓に見えない当たり判定を作ることになる |
| 窓サイズを設定にして、入らない文字を自動で縮める | 利用者が選んだ文字サイズを黙って上書きする。「押しても何も起きないボタンを置かない」（ADR 0010）と同じ筋で、**言ったとおりにならない設定を置かない** |
| 幅を「いま出ている文字列」で測る | 数字の字幅が違う書体では毎秒わずかに変わり、窓が震える（ADR 0008:33-34 の実測） |
| 余白を「狭い・普通・広い」の 3 段にする | 文字サイズが 24〜160pt と広いので、同じ段でも見え方が全く違う。数値で持つほうが一貫する |
