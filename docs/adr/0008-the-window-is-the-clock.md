# ADR 0008 — 窓そのものを時計にする。枠と設定タブをやめる

- 状態: 受理
- 日付: 2026-09-04
- Issue: #36
- 影響する規則: ARC-005 / ARC-011 / FR-030 / FR-045 / FR-047 / FR-050 / SWG-001 / SWG-003 / CNF-004

## 文脈

M0.1 までの画面は `JTabbedPane` の Clock / Settings で、OS のタイトルバーを持つ普通の窓だった。
仕様としては正しく動いていたが、**机の上に置いておきたいものには見えなかった**。

- タイトルバーと 3 つの窓ボタンが、時刻より先に目に入る
- 設定タブが常に見えているので、「操作するアプリ」に見える
- 既製の Swing 部品（Metal / Nimbus）の見た目が、時計の見た目を決めてしまう

施主要件は次の 3 つである。

1. 枠は通常は出さない。ホバーしたときだけ操作を出す
2. 設定はタブではなく、ギアのアイコンから開くモーダル
3. 用意された部品ではなく、デザインを練ったインターフェースにする

デザインは先に作った: https://claude.ai/code/artifact/df5a6479-a4bd-4bbe-a656-80b7781abd3d

## 決定

**窓そのものを時計にする。** `setUndecorated(true)` で枠を捨て、必要な操作は自分で持つ。

- ホバーで右上にクロームが出る（移動 / 設定 / 終了）。140ms で現れ、240ms で消える
- **窓のどこを掴んでもドラッグで動く。** 移動アイコンは「掴める」ことを教える役目である
- **窓の大きさは設定に従う。** 枠が無いので利用者が端を掴んで広げられない。
  文字を大きくして「05:14:..」と切れて出るのは、窓が時計そのものだという前提と噛み合わない
- 大きさは「いま出ている文字列」ではなく「**起こりうる中で最も広い文字列**」で決める。
  等幅でない書体では毎秒わずかに幅が変わり、窓が震えるため
- 設定はモーダル。一覧・書体・色の 3 画面を持ち、選択肢の多いものだけを別画面へ出す
- モーダルは**入力を塞がない**（modeless）。設定の変更は時計へ即座に出るので、
  見えるように窓を動かせるほうがよい
- モーダルの配色は**時計の背景色の明るさに追従する**。利用者が選ぶのは時計の 2 色だけで、
  モーダルの色はそこから決まる従属的な値である
- つまみ・分節・帯・札・アイコンはすべて自分で描く。既製の見た目を出さない
- 角丸は試して、環境が断ったら諦める。半透明の可否を読む手段はアプリに無い（ADR 0006）

## 強制

- **active**: UI 状態の反映は `render` で始まるメソッドの中だけ（CNF-004）
- **active**: 可変状態の隔離区画が増えていないこと（ArchUnit）。
  ドラッグの掴んだ点とクロームの見え方は Swing 部品の描画状態であり、既存の区画に入る
- **planned**: 「窓が実際にどう見えるか」の検査。
  ここは**目視でしか確かめられない**。だから実機で見て、記録に残す（QLT-012 / gate-proofs 11）

## 結果

得られるもの:

- 時刻だけが浮いている見た目になった。置いておけるものになった
- 設定が「いじるときだけ前に出る」ようになり、常に見えていない
- 見た目の正本がデザインとコードの 2 か所にあり、どちらも読める

失うもの:

- **OS の窓装飾を捨てたので、移動・終了・大きさを自分で持つ義務が生まれた。**
  最大化・スナップ・タスクバーからの操作など、OS が無料でくれていたものは無い
- 窓の端を掴んでの手動リサイズができない（大きさは設定に従う）
- Swing の描画コードが増えた。部品 1 つずつに描き方の責任がある

## 実機で踏んだこと（実装中に見つけた 4 件）

いずれも**画面を見るまで分からなかった**。単体テストは全部緑だった。

| 何が | どう直したか |
| --- | --- |
| 文字を大きくすると時刻が「05:14:..」と切れた | 窓の大きさを設定に従わせた（最も広い文字列で計算） |
| ポインタが既にある位置に窓が出ると、クロームが永久に出てこない | `entered` だけでなく `moved` でも出す。クローム自身も自分で出る |
| 設定の一覧で色見本が右へ寄った | `BoxLayout` は子の `alignmentX` が混ざると崩れる。全部の子に左寄せを言う |
| 書体の分類チップが縦に潰れた | `BoxLayout` をやめて `FlowLayout` にした |

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| タブのまま、見た目だけ作り替える | 設定が常に見えている構図が変わらない。「置いてあるもの」にならない |
| クロームを下端の中央に置く | 対称で美しいが、日付行と近く、窓を低くすると必ず干渉する |
| クロームを左端の縦レールにする | 時刻を中央から押しやる。ホバーの度に文字が動いて見える |
| 設定を別ウィンドウ（枠あり）にする | 枠を捨てた理由がそのまま設定画面に戻ってくる |
| モーダルを本当に modal にする | 設定を変えた結果が時計に出るのに、その時計を動かせなくなる |
| 移動アイコンでしか動かせないようにする | 掴める場所が 32px 四方しか無い。窓を動かすたびに狙う必要がある |
| 窓の端でリサイズできるようにする | 枠の無い窓に見えない当たり判定を作ることになる。大きさは設定で決まるほうが一貫する |
| 既製の `JColorChooser` / `JComboBox` を使う | 施主要件そのものに反する。既製の見た目が時計の見た目を決めてしまう |
