## 2. 🔴 いちばん伝えたいこと — 「窓は自分がどこに居るか知らない」

複数モニタで 2 回、設計の前提を間違えた。**どちらも実機の数字に否定された。**

### 間違い 1（ADR 0018）: 「窓は自分が載っている画面の変化を知る」

**知らない。** JDK 21 は窓が別の画面へ移っても `GraphicsConfiguration` を差し替えない。
実測では、窓が 150% の画面へ深く入り込んでも `scale=1.25` のままだった。
⇒ ADR 0018 の実装は**実機で一行も実行されていなかった**。マージしたあとで分かった。

### 間違い 2（ADR 0019 の当初案）: 「窓の画面の変換を見越して打ち消す」

打ち消す算術は正しかったが、**鍵にした画面が信用できなかった**。
`getGraphicsConfiguration()` は、ピア自身の `setLocation` 変換に対しても古い。

```text
狙った実ピクセル -600 → 窓の画面(0, 1.25) で逆変換 → setLocation(-480)
ピアが実際に置いた場所 → +1200 = 左画面(-3840, 1.5) の変換を掛けた値（1px 単位で一致）
```

### 正しかったもの: ポインタの画面を信じる

ドラッグ中、ポインタは常に窓の上にある。**ピアが見ている現実に近いのはポインタの画面**である。

## 3. Java のデスクトップは 1 つの座標空間ではない（必読）

| 画面 | Java の原点 | Java の大きさ | 尺度 | 実際 |
| --- | --- | --- | --- | --- |
| 主 | **(0,0)** | 3072×1728 | 1.25 | (0,0) 3840×2160 @125% |
| 左 | **(-3840,0)** | 2560×1440 | 1.5 | (-3840,0) 3840×2160 @150% |
| 右 | **(3840,0)** | 2194×1234 | 1.75 | (3840,0) 3840×2160 @175% |

🔑 **原点は実ピクセル、大きさは論理ピクセル。単位が混ざっている。**
だから **-1280〜0 はどの画面にも属さない穴**になる。

変換の規則（実データで検算済み）:

```text
実ピクセル = 原点 + (Java 座標 − 原点) × 尺度
Java 座標  = 原点 + (実ピクセル − 原点) ÷ 尺度
```

座標源も 2 つあって食い違う（境界で **1282px**）:

- `MouseEvent#getXOnScreen()` … **窓の画面**の尺度で返す（ポインタが別の画面に入ると嘘になる）
- `MouseInfo#getPointerInfo()` … **ポインタの画面**の尺度で返す。画面も一緒に答える ← **こちらを使う**

⚠️ **窓の幾何に触るときは、まず `ScreenSpace` と ADR 0019 を読むこと。**
「デスクトップは連続している」と仮定したコードは、混在尺度の環境で必ず壊れる。

## 4. 検証の選び方が変わった（QLT-013）

**`./gradlew check` は完了の定義のまま。変わったのは「いつ・何回回すか」。**

| 変えたもの | 回すもの |
| --- | --- |
| 文書・コメントだけ | 規則 ID・waiver・モジュールグラフに触れたときだけ `validateConformance`。他は何も回さない |
| あるモジュールの振る舞い | そのモジュールの `test` ＋ 直接の呼び出し元 |
| UI | そのモジュールの `test` ＋ **`./gradlew run` で目視**し、gate-proofs に記録 |
| 共通基盤（Gradle 設定・`config/`・build-logic・JDK・lock） | ここで初めて全件 `check` |

- 成功の再利用の鍵は **`git rev-parse HEAD^{tree}`**。コミット ID ではない
- 手元の全件は「引き渡し前に最大 1 回」。**完了の判定は CI が PR で 1 回**
- 正本は `docs/DEVELOPMENT_WORKFLOW.md` 第 9 節。PR 本文に「回さなかった検査とその理由」を書く

## 5. 実機（複数モニタ）の測り方 — WSLg では何も証明できない

🔴 **WSLg には複数画面も per-monitor DPI も無い。** 複数モニタの修正は、
**単体テストでも `./gradlew run` でも検証できない**。実機で測るしかない。

手順は `docs/quality/gate-proofs.md` 第 25 節に書いた。要点:

1. 配布物を作る（`gh workflow run release.yml --ref <branch>`）。**ポータブル zip なら
   インストールせずに試せる**。`app/NeNe Clock.cfg` に `java-options=` を足せば
   システムプロパティも渡せる
2. 合成ドラッグ（`SendInput`）で人の手を借りずに再現する
3. 測定プロセスは **`SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)` を宣言する**

### ⚠️ 試験の道具が嘘をついた 2 件（両方とも踏んだ）

- **DPI 非対応のプロセスで測ると、全モニタが 96dpi（100%）に見える。**
  「拡大率は全部同じだ」と誤読しかけた
- **画面がロックされていると、合成クリックはロック画面に吸われる。**
  窓は動かないのに数字だけは出るので、「直っていない」と読み違える。
  ⇒ 押下点に本当に対象の窓が居るかを `WindowFromPoint` で確かめてから始める

🔑 **測定が成立していない状態と、成立して失敗した状態を混ぜない。**

## 6. 地雷（今日足されたもの）

初日〜09-04 の分は [2026-09-03](2026-09-03.md) / [2026-09-04](2026-09-04.md) を見ること。

1. **`frame.getGraphicsConfiguration()` を信じない。** 窓が別の画面へ移っても更新されない
2. **`MouseEvent#getXOnScreen()` を窓の移動に使わない。** ポインタが別の画面に入ると嘘になる
3. **`setLocation` に渡した値には、ピアが必ず変換を掛ける。** 正しい Java 座標ではなく
   「変換されたあとに正しくなる値」を渡す
4. **窓の大きさは、外から変えられたら戻す。** `componentResized` で preferred size に戻している。
   これが無いと DPI 変更のたびに ×1.2 が累積する
5. **`record` は検証を伴う値型に使えない**（既出だが、`WindowPadding` でまた当たった）
6. Error Prone: **`UnusedVariable` は `-Werror` で落ちる。** 使わなくなったフィールドは消す。
   **`DefaultCharset`** も落ちるので `Files.newBufferedWriter(..., UTF_8, ...)` を使う
7. PowerShell: 関数呼び出しは `Scale` であって `Scale()` ではない。`"-30" * 3` は文字列になる

## 8. 作業の型（今日 5 PR・ADR 4 本で機能した）

1. **Issue を先に立てる。** 施主の言葉を根拠として引用し、**やらないこと**を書く
2. **設計を変えるなら先に ADR。** 却下した選択肢を必ず書く（今日はそれが 2 回効いた）
3. **見えないものを直しにいかない。** 実機の数字が要るなら、先に測れる状態を作る
4. **直して効かなかったら、見立てを疑う。** 直し方を変える番ではない（ADR 0012 / 今日 2 回）
5. **決め打ちできないときは、候補を 1 つのビルドに入れて測定に選ばせる。**
   選んだら**分岐を消す**（ARC-001）
6. **実装に予測を書かせてから測る。** 外れたら、理解していない何かが残っている印である
7. 検証は差分から選ぶ（QLT-013）。**回さなかった検査とその理由を PR に書く**
8. **消せないものを消したと書かない。** 残った欠陥は Issue にして、ADR と gate-proofs の両方に残す
