## 3. Store（MSIX）について分かっていること

正本は [報告](../reports/2026-10-04-store-msix-research.md) と [ADR 0020](../adr/0020-the-store-is-a-fourth-channel-wrapped-from-the-same-app-image.md)。要点だけ書く。

- **製品コードを変えずに包める。** `packageInstaller` が作る app-image をそのまま `makeappx` に渡す。読み取り専用の場所に入れても動く
- **設定は「読むのは本物・書くのは専用」。** MSI 版から乗り換えた人は設定を引き継ぐが、Store 版で変えたあとは別々になる。
  Loupe（ファイル）とは動きが違う。README に書く必要がある
- **CI で作れる。** `makeappx` は `C:\Program Files (x86)\Windows Kits\10\bin\10.0.26100.0\x64\`。PATH には無い
- **版は 1.0.0 以上が要る**（Store は先頭が 0 の版を受け付けない）。上げるのは施主が決めてから
- 制度（Microsoft が署名する・プライバシーポリシーが必須など）は Loupe のリポが一次資料で裏を取っている。
  `C:\Users\info\WORKS\NeNeLoupe\docs\reports\2026-10-03-store-msix-research.md`。Loupe のリポは読むだけで、触らない

決まっていること（施主 2026-10-04）: #97 は 1.0.0 の前・#101 は後。掲載ページは日英。
決まっていないこと: ADR 0020 の受理。アプリ名 `NeNe Clock` の予約（施主の手番）。

申請までの作業は報告の B 節に Issue の切り方の案がある。**まだ Issue にしていない**（ADR が案のため）。

## 4. 実機の実測のやり方（今日できた型）

- **施主は MSI 版を常用している。** 実測の前に `reg export HKCU\Software\JavaSoft\Prefs\io\github\hideyukimori\neneclock` で控えを取り、
  終わったらもう一度書き出して SHA-256 を比べる
- 仕組みを知るための書き込みは、**本物のキーの隣に検証用のキーを作って**行う。本物は読むだけ
- パッケージの文脈で何かを動かすには `Invoke-CommandInDesktopPackage`（開発者モードが要る。施主の PC は有効）
- 開発者モードの登録（`Add-AppxPackage -Register`）は昇格が要らないが、アプリは書ける場所から動く。
  読み取り専用の場所を測るには本当に入れる必要があり、**信頼ストアの書き換えはリナの権限では通らない。**
  スクリプトを置いて施主に実行してもらう（`%LOCALAPPDATA%\NeNeClockProbe\run-me.ps1` が今日のもの）
- 実測の置き場はリポジトリの外。鍵と証明書をリポジトリに入れない
- WSL から PowerShell を呼ぶと出力が cp932 で返る。`iconv -f cp932 -t utf-8` を通す

`%LOCALAPPDATA%\NeNeClockProbe\` は残してある。施主の設定の控えが入っているので、**消す前に施主に確かめる。**
