## 2. 次の 1 手 — #150 読めなかった設定を上書きしない

**決定と設計メモは Issue #150 が正本。** 要点だけ:

| 読めなかった理由 | 動き |
| --- | --- |
| 未来の版（`UNSUPPORTED_SCHEMA`） | **読み取り専用**。保存しない。設定画面で伝える |
| 壊れた値（`INVALID_VALUE`） | 元の値を**退避してから**既定値で保存を再開。伝える |
| 初回（`ABSENT`） | いまのまま |

- 🔴 **ADR を先に書く**（施主の指示）。ADR 0003 の却下表「移行できない版を黙って既定値にする」と、合成ルートが黙って既定値に落としている食い違いもその ADR で解く
- hub 経由の決定は「両方とも読み取り専用」だったが、壊れた値に当てると**一度壊れた利用者が二度と保存できなくなる**ので、施主に直接聞いて「版で分ける」に変わった。hub にはまだ伝えていない（報告に含める）
- 再現テストを先に書いて落ちることを確かめてから直す。1 修正 1 PR
- 文言を足すと設定画面のフッターが変わりうる。通常時の見た目が変わったら、掲載のスクリーンショットを撮り直す

## 5. 今日の教訓

- **差分から選ぶ手元の検証は「モジュールの `check`」を単位にする。** `test` だけ回して、テストソースの Checkstyle（`FileLength` 400 行）を CI で落とした（PR #140）。
  上限は動かさず、テストを別のクラスに分けた
- **UI のテストは headless なので、画面を作る再現テストは書けない。** 代わりに「規約検査で書き方を固定する（CNF-014）＋実アプリを起動して記録する（gate-proofs）」で代えた。
  実アプリの確かめ方: `installDist` の jar を classpath に載せた小さな Java から `NeNeClockApplication.main` を呼び、`Frame.getFrames()` で窓を掴んで
  `WindowEvent` を送る・ラベルの `text` の変化を聞く・`paintAll` で画像に描き出す。設定は `-Djava.util.prefs.userRoot` で使い捨ての場所へ向ける
- **講評の【確認】も鵜呑みにしない。** 数えると講評より悪かった（15 → 25 回/秒）ものも、条件付きでしか起きないもの（版上げ直後の保存だけ）もあった。
  逆に講評が見落とした穴（Alt+F4）は、事実確認の途中で見つかった
- **施主判断が中継されてきたら、実装の前に落とし穴を確かめる。** 「両方とも読み取り専用」は、そのまま作ると利用者を詰ませる形だった。施主に直接聞いて直した
